# Long-Term Novel Benchmark

## Corpus

The dedicated real NovelForge continuity project contains six approved chapters, generated and approved through the actual application workflow. Recorded word counts were approximately 1,761, 1,254, 1,272, 2,748, 1,220, and 1,279 words in the six-chapter draft records. The corpus includes deliberate continuity material around Mara, Elias, Ivo, Northglass, the river, injuries, promises, mysteries, and objects.

## Provider comparison

The six approved chapter texts were captured to the local Tencent gateway as a derived benchmark backfill, without modifying MongoDB. Tencent accepted all six captures. Direct recall for long-horizon queries about the injury, promise, location holder, character knowledge, unresolved mysteries, and five-year disappearance returned no memories. Native retrieval returned relevant records in the matched project comparison.

## Acceptance status

The required 10/20-chapter matched writing-quality comparison was not claimed. It would be invalid to compare prose when Tencent supplied an empty context packet. Synthetic 25/50/100-chapter degradation measurements were likewise not claimed for Tencent for the same reason.

## Next valid experiment

Configure the official gateway with a supported FTS or embedding path, rebuild the same six-chapter derived corpus, and then run identical 10-chapter writing requests with the same strong writer model and the same authority packet. Only that experiment can answer whether Tencent improves long-range continuity or prose quality.
