# NovelForge Real Novel Memory and Context Audit

## Production mode

The project reported:

- mode: `native`;
- default mode: `native`;
- Native available;
- Tencent available but experimental and non-authoritative;
- MongoDB story systems authoritative;
- provider memory derived retrieval only.

Phase D and Tencent were not enabled for writing. This audit did not alter memory architecture or defaults.

## What Chapter 1 contributed

After Chapter 1 approval, the context endpoint reported 32 candidate details. The candidate extraction included Renn, the field-engineer/disaster-mapping background, Lira, mother, Darin, Harwel, river/levy/Bleed, past-life regret, seam perception, and memory cost. This is the correct general direction for a candidate layer.

The approval change reported `canon_changed=false` and `new_information=candidate`, so the system did not silently convert the extraction to canon. That boundary is good, but the author-facing workflow did not explain how to review those candidates.

## What later writing actually received

Chapter 2 through Chapter 10 context packets reported no new candidate extraction because those chapters remained drafts. Their carried context still included large Develop planning objects and provisional items, including:

- Kael as a provisional protagonist;
- a farm and old well;
- “The Buried Sky”;
- “The One Who Notices”;
- “A Gift, a Wound, or a Claim”;
- “The Hidden Fault in the Local World”;
- “The Cost of Belonging”;
- “The Price of Seams.”

The latest context packet after revision was approximately 266,159 tokens inside a 900,000-token context budget and a 1,048,576-token model window. The retrieved-memory list was dominated by the provisional Kael character, provisional plot threads, and the provisional world object. Active context, working memory, compressed memory, important memory, recent memory, and core memory were empty in that packet.

This is a large-context failure, not a small retrieval miss. A model can see formally labeled exploratory material and still treat it as story direction because it is prominent, repeated, and semantically coherent.

## Correctly remembered

- broad seam/memory-cost direction;
- river/levy/Blight/Darin motifs from generated prose;
- the general old-life regret and practical-eye idea;
- the existence of a long mystery and constrained progression;
- approved Chapter 1 remained the latest approved chapter;
- Mongo authority was preserved and candidate extraction was not canonized.

## Forgotten or retrieved poorly

- Chapter 2 lost Renn's gender, age, and present household identity.
- The author's intended disaster-mapping/emergency-infrastructure background was displaced by the provisional archivist/cartographer/farm plan.
- The river-working settlement was mixed with a provisional subsistence farm and well.
- Rejected alternatives did not appear as a visible, enforceable rejection ledger.
- Later chapters had no candidate extraction or intelligence enrichment, but the UI did not make that boundary obvious.
- The strongest retrieved objects were planning abstractions rather than the smallest approved facts and recent prose needed for continuation.

## Memory conclusion

Native Phase C behavior was preserved, and there is no evidence that Phase D or Tencent caused the writing failures. The immediate improvement is authority-aware context assembly: approved facts and recent approved prose must outrank provisional planning, and provisional records should be excluded from drafting unless the author explicitly asks to explore them. The retrieval system also needs a compact “why this was selected” view so an author can see when a provisional item is influencing a draft.
