# NovelForge Narrative Studio V2 - Phase 1B Implementation Plan

Plan date: 2026-06-14

Source of truth:

- `PRODUCTION_ARCHITECTURE_AUDIT.md`
- `DATABASE_MODEL_AUDIT.md`
- `AGENT_ARCHITECTURE_AUDIT.md`
- `PHASE_1A_COMPLETION_REPORT.md`

Scope: Story Readiness Foundation only. This phase does not add chapter
writing, prose generation, WriterAgent, EditorAgent, DialogueAgent,
ArtifactAgent, ForeshadowAgent, or large-scale automatic arc expansion.

## Current Architecture Summary

Phase 1A routes normal cycles through `OrchestrationServiceV2`, which detects
project changes, traverses an impact graph, persists selected and skipped
agents, and executes only selected agents through `NarrativeStudioService`.
Provider throttling, budgets, encrypted settings, ownership checks, bounded
memory embedding versions, and orchestration inspection are active.

Planning data is still inherited from the pre-V2 architecture:

- `story_arcs` has two live schemas, title-based identity, no stable arc ID,
  no approval lifecycle, no chapter range, and no readiness state.
- `story_timelines` is a flat, duplicated, all-at-once artifact generated by
  ArcArchitectAgent.
- Character development is stored in global character and journey documents,
  not arc-scoped progression records.
- Reader knowledge, character knowledge, and world truth are not separated.
- Foreshadowing and artifacts lack normalized lifecycle and relationship data.
- Questions and AI concerns are not deterministic readiness requirements.
- `compressed_memories` is not used by the production agent path, while agents
  still receive generic project retrieval without bounded agent-owned memory.
- The workspace can display arcs and a flat timeline but cannot express
  readiness, approval, uncertainty, or knowledge visibility.

## Problems To Resolve

1. Drafting readiness cannot be calculated or explained.
2. The system implicitly treats whole-story planning as the planning unit.
3. Future unknowns cannot be represented without appearing incomplete or
   erroneous.
4. Arc approval and drafting eligibility are absent.
5. Existing timeline generation encourages exhaustive future planning.
6. Character change has no arc-specific state transition ledger.
7. Hidden reader knowledge cannot be represented independently of character
   knowledge.
8. Foreshadow seeds and artifacts cannot link consistently to arcs, timeline,
   characters, or knowledge.
9. The orchestrator does not classify Phase 1B planning changes.
10. Agents have no bounded, compressed, agent-specific memory.

## Proposed Architecture

### Deterministic Readiness

Add `ReadinessService`, a non-AI authority over readiness evaluation. Readiness
categories and titles remain free-form strings; the service will not contain a
closed category enum or a fixed checklist.

Readiness records may be project-wide or arc-scoped. Evaluation uses persisted
record attributes:

- `blocking=true`, `priority=required`, and status below `approved` is a
  blocker.
- `approved` and `ready` satisfy a requirement.
- Evidence can advance a missing item to `discussed`, but deterministic
  evaluation never invents approval.
- An approved or active arc with all applicable required blockers satisfied is
  drafting eligible.
- An arc with some useful evidence or satisfied requirements but unresolved
  blockers is `PARTIALLY_READY`.
- An empty or wholly blocked arc is `NOT_READY`.
- Future arcs do not participate in another arc's drafting gate.

The service will persist calculated readiness status on each arc and return
reports containing counts, blockers, missing items, recommendations, evidence,
and drafting eligibility.

`ReadinessAgent` may propose or discuss readiness records, but it cannot
override the deterministic gate.

### Arc Lifecycle

Normalize `story_arcs` around:

- stable `arc_id`;
- lifecycle `draft`, `discussed`, `approved`, `active`, `completed`,
  `archived`;
- `chapter_range`;
- calculated readiness status;
- purpose/goal/conflict/stakes fields;
- additive planning fields retained from existing records.

The API will support creating, editing, and transitioning individual arcs.
ArcArchitectAgent will be instructed to work incrementally and persist draft
arc proposals without requiring all future arcs.

### Timeline V2

Add `timeline_entries` as the workspace timeline authority. Entries are
arc-scoped where known and carry stable IDs, lifecycle, certainty, dependencies,
and optional chapter ranges.

`certainty=unknown` is a valid persisted state. Unknown entries may contain a
placeholder title and empty summary. The UI will group entries by arc and
visually distinguish known, probable, and unknown areas.

Legacy `story_timelines` remains available for rollback but is no longer the
V2 read/write path. Existing records will be migrated idempotently into V2
entries without deleting legacy data.

### Typed Planning Ledgers

Add:

- `character_progressions`: one character transition per arc, with current and
  desired state plus skills, powers, beliefs, relationships, maturity, trauma,
  and goals.
- `knowledge_entries`: typed `WORLD_TRUTH`, `READER_KNOWLEDGE`, and
  `CHARACTER_KNOWLEDGE` records with knowers, non-knowers, learning method,
  falsehood, confidence, source, and reveal target.
- `foreshadow_registry_v2`: seed, planting location, payoff target, and
  lifecycle.
- `artifact_registry`: owner, powers, hidden powers, cost, limitations,
  history, future relevance, and typed links.

The hidden reader layer will be represented by a reader-knowledge record whose
`known_by` includes readers and whose `not_known_by` includes the relevant
characters, optionally linked to a separate world-truth record.

`KnowledgeAgent` owns AI-produced knowledge proposals. No ArtifactAgent or
ForeshadowAgent will be created.

### Bounded Agent Memory

Add `agent_memories` with agent ownership, memory tier, importance, source
identity/version, active state, and timestamps.

Before every agent call, the context packet will receive:

- bounded compressed summaries;
- bounded important memories;
- bounded recent memories.

After execution, the agent summary becomes recent memory. Approved decisions,
canon, and explicitly important facts become important memory. Every configured
cycle interval, older recent memories are compacted into deterministic summary
records. Cleanup retains bounded active rows per tier and removes stale
versions. Generic semantic retrieval remains available as supporting context.

### Dynamic Orchestration

Extend the Phase 1A graph rather than replacing it:

- readiness changes select ReadinessAgent and affected arc planning only;
- knowledge changes select KnowledgeAgent and related mystery/arc analysis;
- arc and Timeline V2 changes select ArcArchitect/Pacing as appropriate;
- character progression changes select CharacterJourney/Relationship;
- foreshadow changes select Mystery/ArcArchitect;
- artifact changes select only relevant world/power/character planning agents.

The planning-agent registry will include ReadinessAgent and KnowledgeAgent.
Every plan will still record selected and skipped reasons. Existing call,
depth, budget, enablement, rate-limit, and no-change protections remain active.

## Database Changes

Add:

- `story_readiness`
- `timeline_entries`
- `character_progressions`
- `knowledge_entries`
- `foreshadow_registry_v2`
- `artifact_registry`
- `agent_memories`

Normalize existing `story_arcs` in place. Do not add a replacement arc
collection.

Planned indexes:

- unique readiness identity by project/item ID;
- readiness report lookup by project/arc/status/priority/blocking;
- unique arc stable ID by project;
- arc lifecycle and order lookup;
- unique timeline entry ID by project;
- timeline lookup by project/arc/certainty/order;
- unique character progression by project/arc/character;
- unique knowledge entry ID by project;
- knowledge lookup by project/type/arc;
- unique foreshadow entry ID by project;
- foreshadow status/payoff lookup;
- unique artifact entry ID by project;
- artifact owner/status lookup;
- unique agent-memory source version;
- agent-memory lookup by project/agent/tier/active/update time.

Migration will assign stable IDs, map legacy arc statuses, add chapter/readiness
fields, migrate legacy timeline rows to V2 entries, deduplicate by legacy
source identity, and install named indexes. Legacy collections will not be
deleted.

## API Changes

Add project-owned CRUD/read APIs for:

- readiness items and readiness reports;
- individual arcs and lifecycle transitions;
- Timeline V2 entries;
- character progressions;
- knowledge entries;
- Foreshadow Registry V2;
- artifact registry;
- bounded agent-memory diagnostics.

All child mutations will validate project ownership and linked arc IDs.
Mutations emit typed project events so the next production cycle can classify
their impact.

The readiness report endpoint will accept an optional `arc_id` and return
`READY`, `PARTIALLY_READY`, or `NOT_READY`, blockers, counts, and
`drafting_eligible`.

The existing `/draft-scenes` planning endpoint will require an explicitly
eligible arc before invoking ScenePlannerAgent. It will remain scene planning,
not prose generation.

## UI Changes

Add minimal workspace sections:

- Readiness Dashboard: Ready, Blocked, Missing, Recommended, report status,
  and drafting eligibility.
- Arc Board: Draft, Discussed, Approved, Active, Completed, with readiness and
  chapter range.
- Knowledge View: Reader Knowledge, Character Knowledge, World Truth, and
  visibility differences.
- Timeline V2: arc-grouped Known, Probable, and Unknown entries.

The current workspace shell and Phase 1A Orchestration Inspector remain intact.
No chapter editor or prose surface will be added.

## Migration Plan

1. Add an idempotent Phase 1B migration and standalone runner.
2. Normalize legacy arcs in place with stable IDs and lifecycle fields.
3. Migrate legacy timeline records into `timeline_entries` using legacy source
   IDs for deduplication.
4. Install all Phase 1B indexes.
5. Deploy backend readers that tolerate both normalized and legacy arc fields.
6. Activate new APIs and Story Bible sections.
7. Activate agent-specific memory for production agent calls.
8. Deploy UI sections against the new typed APIs/read model.

## Rollback Plan

1. Stop new cycles and planning mutations.
2. Restore the pre-Phase 1B application while retaining Phase 1A.
3. Leave additive Phase 1B collections and indexes in place; Phase 1A does not
   read them.
4. Legacy `story_timelines` remains untouched and can resume as the old read
   path.
5. Arc normalization is additive. Legacy title, goal, order, and
   `completion_status` fields remain available.
6. Disable ReadinessAgent and KnowledgeAgent assignments if provider behavior
   must be isolated without rolling back the data model.
7. Retain `agent_memories`; older code ignores it and generic memory embeddings
   remain intact.

## Acceptance Gates

Phase 1B is complete only when:

- Arc 1 can be drafting eligible without Arc 2 or Arc 3 completion;
- Arc 2 can be partially ready and continue planning;
- Arc 3 can retain explicit unknown timeline entries;
- readiness, progression, knowledge, foreshadow, and artifact ledgers work;
- the hidden reader layer is representable without contradiction;
- ReadinessAgent and KnowledgeAgent are demand-selected;
- agent memory is bounded and compacted;
- the Phase 1A dynamic production path remains active;
- no chapter writing, prose generation, or forbidden agent is introduced;
- backend, frontend, build, Playwright, migration, and real Gemini checks pass.
