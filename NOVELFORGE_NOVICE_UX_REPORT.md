# NovelForge Novice UX Report

## Current-source browser journey

A novice can now see the following without knowing internal architecture:

1. Story Studio says the project has one chapter and identifies Chapter 1 as the latest approved chapter.
2. The Writing link opens a chapter library with status, word count, active version, continuity state, context state, and clear actions.
3. `Edit Chapter 1` opens the prose directly and explains that saving creates a protected new version.
4. Story Studio keeps old answers visibly historical and offers refresh against current story state.
5. An ambiguous creative request asks one useful question rather than guessing or mutating.
6. Suggestions are labeled as suggestions, with Confirm and Not a story fact actions.

## Remaining friction

The page still exposes specialist result-card language and some operational status wording. Selection-based AI editing is present in the source editor but still needs a fresh-provider browser exercise to prove the complete select-preview-accept loop. The current project also displays a continuity warning from earlier data, which is honest but not yet explained as clearly as it could be.

## Verdict

The main write/talk/edit loop is understandable without learning agents, Narrative Intelligence, MongoDB, or provider routing. It is not yet a claim of a finished literary-product UX: humanization quality, selection revision live proof, and the final long-history visual pass remain open.
